# Getting Started

Use a release, or build from source. Or [try the live demo](/demo).

## 1. Get DeckBridge

### Option A — Packaged release (recommended)

:::caution
Releases are **tested on macOS**. Windows and Linux get less testing. Linux needs
**glibc 2.38+** (Ubuntu 24.04+, Debian 13+), or build from source.
:::

Download a [release](https://github.com/lukasMega/DeckBridge/releases), unzip it, and run
it. No Node.js needed.

#### Latest downloads

<Downloads />

```bash
./deckbridge        # macOS / Linux
deckbridge.exe      # Windows
```

macOS and Windows include a tray icon. On Linux, run `./install-desktop.sh` once for an
app menu entry (no root). Run it again if you move the folder.

<details id="option-b--build-from-source">
<summary><b>Option B — Build from source</b></summary>

Install [mise](https://mise.jdx.dev), Rust, and **libhidapi**:

- macOS: `brew install hidapi`
- Debian/Ubuntu: `sudo apt install libhidapi-dev`

```bash
cd deckbridge
mise run start      # build everything + run
# or
mise run compile    # produce a standalone ./deckbridge binary
```

mise downloads txiki.js. On macOS x86_64 it builds it locally (needs git, cmake, npm,
libffi). `TJS_FROM_SOURCE=1` forces a local build (needed on Linux older than glibc 2.38).

</details>

## 2. Plug in your deck

Connect [supported hardware](./introduction.mdx#supported-devices). On macOS, grant
**Input Monitoring** access. DeckBridge scans every 3 seconds (up to 30 if scans are slow).

## 3. Run it

Start DeckBridge. It opens your deck and serves:

- CORA on TCP **5343 / 5344**
- web UI at **http://localhost:3000** (or a free port in 33011–33099 if 3000 is busy)

The tray icon shows the status:

|                   Tray icon                    | State      | Meaning                                              |
|:----------------------------------------------:|------------|------------------------------------------------------|
| ![Gray tray icon](./img/tray-disconnected.png) | **gray**   | no deck                                              |
|  ![Yellow tray icon](./img/tray-usb-only.png)  | **yellow** | deck connected, ready to pair with the Elgato app    |
|    ![Green tray icon](./img/tray-full.png)     | **green**  | deck open *and* Elgato app connected                 |

On macOS it sits in the menu bar. Menu: **Open Web UI**, **Check Requirements**,
**Restart Elgato App**, **Quit**.

## 4. Pair with the Elgato app

Open Elgato Stream Deck or Companion on any computer on the **same LAN**. In the web UI,
answer **Already paired with your control app?**

- **Yes, already paired** — **Open Elgato app** (if stopped) or **Restart Elgato app** (if running).
- **No, set up pairing** — **Pair manually** shows the steps and the pairing address.

App buttons act on the DeckBridge computer. For another computer's app, open it there.

Extra decks must be different models. Pair each on its web UI card and port (5345,
5347, …). See [Multiple decks](./features.md#multiple-decks).

## Verify your setup

Open **http://localhost:3000** (or tray → **Open Web UI**) and check live keys and logs.
Tray → **Check Requirements** runs [diagnostics](./features.md#requirements).

## Troubleshooting

More: [Troubleshooting & Diagnostics](./troubleshooting.md).

- **No device** — check USB. On macOS, grant Input Monitoring.
- **Ports 5343/5344 busy** — stop the other DeckBridge, Network Dock, or ESP32 bridge.
- **Missing libhidapi** — see [source-build steps](#option-b--build-from-source).
- **Linux permission denied** — add a [udev rule](./features.md#permissions).
- **Restrict LAN access** — set `DECKBRIDGE_BIND=127.0.0.1`.
- **Web UI not on 3000** — use tray → **Open Web UI** or the `WebUI: http://localhost:<port>`
  log line. `--webui-port <n>` pins a port (startup fails if busy).

<details>
<summary>Advanced and mock mode</summary>

- `mise run s-advanced` enables advanced controls.
- Mock simulation needs `mise run build-mock`, then `DECKBRIDGE_MOCK=1`. Released binaries
  do not include it.

</details>
