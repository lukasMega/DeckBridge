Every field of every `DeviceModel`, generated from `ts/src/devices/registry.ts`. This is
the page to read when you are porting a deck or chasing a black panel; if you just want
to know whether your deck works, read [Supported devices](./devices.mdx) instead.

The three tables below are **live**: type to filter rows, click a header to sort,
and use the chips to show the columns you care about — most start hidden.
Column names are abbreviated: hover a dotted header (or a column chip) for what
the field means.

How much to trust a value:

- **Measured** — anything on a deck marked tested. The image tuning and key maps of the
  293V3, 293S, K1 Pro, D6 rev. 2 and Mini were derived on hardware.
- **Inherited** — the rebadges copy a tested board field-for-field, by construction, so
  they cannot drift; what is untested is the *assumption* that the board is the same.
- **Inferred** — read out of a reference implementation. Each device lists its sources.
- **Probed at runtime** — only `packetSizeCandidates`: when set, the real output-report
  size is read from the HID report descriptor at `open()` and overrules `packetSize`,
  but only if it is one of the listed values. A wrong packet size is otherwise silent —
  short writes are discarded while `hid_write` still returns success, and the panel just
  stays black.

Adding a deck of your own? [Adding a device](./adding-a-device.md) is the workflow.

## Image spec

How a CORA frame becomes the bytes this panel wants. The `format: 'bmp'` short-circuit in
`image-pipeline` runs before any of this; `transform: 'passthrough'` sends the CORA JPEG
unchanged and is only valid at CORA-native resolution with no rotation, flip or size cap.

## Wire spec

Low-level framing for the Mirabox CORA protocols. Elgato models have no wire spec — their
framing lives in `PROTOCOL_STRATEGY` instead.

## Key maps and CORA identity

Per device: the CORA-index ↔ wire-id mapping drawn as a grid (a wrong map is visible at a
glance), the raw `keyMap`, what the device advertises to the Elgato app, and the splash
transform override. Image and input are resolved independently —
`coraToWireImage[i] ?? i + imageOffset ?? i` for images,
`wireInputToCora[code] ?? code - inputOffset ?? code` for presses.
